# 모미 UI 설계 노트

모임 화면은 참가자와 운영자가 같은 정보를 서로 다른 목적으로 읽는 공간입니다. 참가자는 내 상태를 빠르게 찾고, 운영자는 여러 사람의 상태를 비교할 수 있어야 합니다.

## 내 상태를 먼저 읽게 하기

대기 화면은 내 순번과 전체 대기 인원을 먼저 보여주고, 상세 목록을 아래에 배치합니다. 숫자와 위치를 함께 사용해 색상을 보지 않아도 순서를 이해할 수 있게 합니다.

출석 화면은 참가자마다 항목의 위치를 고정합니다. 출석, 참가비 납부, 지각은 서로 다른 정보이므로 하나의 완료 상태로 합치지 않습니다.

## 좁은 공간에서 게임 현황 보여주기

게임 요약 콘셉트는 게임 순서와 참가자 이름만 표시합니다. 상태는 섹션 제목으로 묶어 같은 문구가 반복되는 것을 줄입니다.

넓은 화면에서는 한 줄에 두 게임을 보여줄 수 있습니다. 실제 모바일 구현에서는 글자 크기를 과하게 줄이기보다, 화면 폭과 글자 확대 설정에 따라 한 줄에 한 게임으로 전환하는 편이 읽기 쉽습니다. 현재 공개 이미지는 두 열 배치를 비교하기 위한 콘셉트입니다.

## 버튼의 강조 줄이기

시작과 완료처럼 자주 사용하는 동작도 채도가 높은 색을 넓게 사용하면 선수 정보보다 먼저 눈에 들어올 수 있습니다. 게임 상태는 짧은 문구로 표시하고, 동작은 아이콘과 라벨을 함께 사용합니다.

상태를 색상만으로 전달하지 않습니다. 채도를 낮추더라도 텍스트와 배경의 대비, 실제 터치 영역은 별도로 확인해야 합니다. 공개 이미지는 시각적 방향을 보여주며 접근성 검증 결과를 대신하지 않습니다.

## 화면 표시 정책과 생명주기 분리

커버 이미지 위의 상태바는 배경과 겹쳐 읽기 어려워질 수 있습니다. 모미 Android에서는 아이콘의 밝기를 결정하는 조건과 화면에 실제 적용하는 처리를 구분합니다.

정책 함수는 현재 화면 조건으로 표시 방식을 결정하고, 화면의 효과는 그 결정을 반영합니다. 화면을 벗어날 때의 복원은 별도로 관리합니다. 이렇게 구분하면 조건별 판단을 테스트하면서 화면 전환의 영향을 다룰 수 있습니다.

이 상태바 사례는 설계 설명을 담고 있습니다. 매칭과 참석 확정 처리의 독립 실행 코드는 [별도 예제](../examples/README.md)에서 확인할 수 있습니다.
